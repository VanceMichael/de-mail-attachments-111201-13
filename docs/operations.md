# 本地运行说明

## 处理合成邮件归档

先运行单元测试，再执行处理命令。处理过程不需要外部站点或真实邮箱。

```bash
python3 -m unittest discover -s tests -t .
python3 -m collector mailbox --messages fixtures/messages.json --db var/mail.sqlite3
```

每封邮件在独立事务内提交：单封失败不影响其他邮件，所有判定（收下、拒绝、隔离）
都会落库。处理中断后，用相同输入重新执行 `mailbox` 即可从归档重放；已处理的邮件
按原始字节摘要识别并跳过，已入库的数据行不会翻倍，拒绝与隔离记录也不丢失、不重复。

## 读懂处理报告

报告按邮件给出五种状态，资料员可据此区分问题层级：

- `rejected_message`：整封不能读，原件已进隔离区，需联系发件方重发；
- `rejected_attachment`：邮件本身可读，是某个附件或压缩成员被拒，查看
  `rejections` 中的 `location` 可定位到具体部件和成员路径；
- `partial_delivery`：有效数据已收下，但可信清单未全部满足，或没有清单可核对；
- `complete`：清单全部满足，本次交付完整；
- `no_data`：邮件可读但没有 CSV 数据，通常是纯转发说明邮件。

`report` 命令汇总最近一次运行的交付判定与拒绝明细；`lineage` 命令按业务行键
回溯该行的全部来源（含转发来源）与修订版本。

## 安全边界

解包全程在内存中完成，不会把附件写到磁盘，也不会执行任何附件。下列情形直接拒绝
并在报告中说明：越界路径（`..`、绝对路径）、符号链接或设备节点、加密压缩包、
超出层数/成员数/总字节/单文件字节上限。限额在 fixtures 的 `limits` 中配置。

## 数据保留

查询模式只读取数据库，不会补采或删除来源数据。证据库包含原始邮件字节与隔离数据，
需要长期留存时备份整个数据库文件即可。数据文件路径均相对项目根目录，切换工作目录
前请确认 `--messages` 与 `--db` 参数。
